Tour

One review loop, in the browser and the terminal.

Each step shows both interfaces on the same synthetic demo data. The keys are the same in both; the browser adds clicks. Every image is a capture of the running application, made without committing anything.

01

Start with the demo.

The demo opens a temporary household of about 2,000 transactions. Edits work as usual and disappear when the process exits.

For your own data, choose Add profile in either interface and pick Monarch, YNAB, Amazon or SimpleFIN. Import bank CSV files with moneyflow provider import.

Quick start
Run either one 
moneyflow web --demo
moneyflow tui --demo

Both share profiles. Pending edits you stage in one appear in the other.

02

Group, drill, search.

g cycles the grouping through merchant, category, group, account and time. In the browser, 1–5 or the sidebar pick one directly.

Enter drills into the rows behind a total and Esc goes back. In the browser, double-click a group or click an earlier breadcrumb. / searches merchant and category names with a regular expression. i shows a transaction's details.

Navigation and search
From an assistant

The MCP server's search_transactions matches literal text, notes included. Results carry transaction IDs that the edit tools accept.

MCP guide
03

Select, then stage an edit.

Space selects rows; in the browser, click a row's box. c changes the category and m renames the merchant. In the browser, the selection bar's Category and Merchant buttons do the same, and double-clicking a cell edits it.

A bulk edit is one undo step. u undoes and U redoes. Some providers do not support every edit; unavailable actions say why.

Editing
Assistants stage edits too

Start the MCP server with --allow-write to register the edit tools. Preview with dry_run, then stage against the current revision. Staged edits join the same pending queue you review in the browser or terminal.

04

Review, then commit.

w opens the review of every pending edit and the rows it affects. In the browser, the pending-edits card's Review button opens it too. Enter commits. If the profile changed since you reviewed, Moneyflow asks you to review again.

From MCP, call review_changes, then commit_changes with the reviewed revision, and poll get_commit_status.

Review and commit
Where a commit goes

Monarch and YNAB commits run as a durable write batch. It can pause for rate limits or a reconnect. Each accepted change is saved as it lands, so a restart does not lose progress. Stop and reconcile keeps what the provider accepted and drops the rest.

Amazon, bank CSV and SimpleFIN commits stay local.

05

Export committed data.

E exports Parquet, CSV or SQLite in either interface: the whole profile or the filtered view. MCP has preview_export and export_transactions.

Exports contain committed data only, never pending edits. Each file's metadata counts the pending edits it left out. Exports are unencrypted analysis files, not profile backups.
