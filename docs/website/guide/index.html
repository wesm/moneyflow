The Moneyflow workflow

Less clicking around.
More understanding.

Start broad. Find the rows that matter. Make the change deliberately.

01

Choose your starting point.

Try a disposable demo first. Then add a profile for Monarch, YNAB or Amazon through the selector.

Each profile owns its data and durable pending work. Switching interfaces does not create another copy of your edits.

Quick start →
Start locally 
./bin/moneyflow tui --demo
./bin/moneyflow web --demo

Demo edits disappear when the process exits. Real profiles persist.

02

Ask a smaller question.

Group by merchant, category, account or time with g. Drill with Enter, search with /, and return with Esc.

On a transaction, i opens details. Use that context before treating an unfamiliar amount as a mistake.

Navigation and search →
Prefer an assistant?

Use MCP to search transactions and inspect returned IDs. Its search is literal and includes notes; the TUI/web search is a regular expression over merchant and category names.

MCP setup and tool reference →
03

Select. Then stage.

Space selects rows. Change a category with c or a merchant with m. A bulk change is one undo unit, not a pile of unrelated keystrokes.

Use u to undo and U to redo. Provider-specific availability tells you which changes can actually be committed.

MCP follows the same boundary

Enable write tools explicitly. Preview using dry_run, then stage against the current revision. Reading data does not authorize a provider write.

Pending edits are shared, durable and reviewable.

04

Review before it leaves the journal.

Press w to review and Enter to begin the commit. A changed revision asks you to review again instead of applying a stale decision.

In MCP, call review_changes, then commit_changes for that revision and poll get_commit_status.

Editing and recovery →
A remote commit is a process

A provider batch can pause for rate limits, reconnect or attention. Follow it to completion. Stop and reconcile keeps remote successes and abandons failed or unsent intent.

Local and Amazon commits stay local.

05

Keep an exact record.

Export Parquet, CSV or SQLite with E, or use MCP's export tools. Choose the full profile or a filtered committed subset.

Exports exclude pending edits. The file metadata records what was captured, so “what I see” and “what I exported” need not be confused.
